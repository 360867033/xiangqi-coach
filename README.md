# 象棋教练 · 皮卡鱼 + 云库 + DeepSeek

给"只会看引擎分数、看不懂为什么"的棋友用的本地讲棋工具。

引擎负责**算**，云库负责**实战经验**，大模型负责**讲**。三者结合，回答的是：

- 引擎推荐的这一步**好在哪**、它想干什么
- 我走的那一步**差在哪**、会被对手怎么惩罚（附引擎预演线）
- 这一步的代价有多大（厘兵 / 胜率），够不够输
- 把具体错误**抽象成棋理**，下次怎么想

三个模式，从"看一步"到"下整盘"：

| 模式 | 干什么 |
|---|---|
| **教练模式** | 分析 / 讲解某个局面或某一手（主力功能） |
| **对弈模式** | 和皮卡鱼下整盘棋（自己选执红还是执黑），也能自己摆一个残局再开局；下完能存棋、导出、送去复盘 |
| **整盘复盘** | 贴一份棋谱，逐手找失着、画局势曲线、出 AI 报告 |

## 一、快速开始

> **首次使用先补两样东西**——仓库里不含引擎，也不含带密钥的 `config.json`：
>
> 1. 下载**皮卡鱼引擎**，解压到本目录下的 `Pikafish/`：
>    - [official-pikafish/Pikafish Releases](https://github.com/official-pikafish/Pikafish/releases)
>    - 或 [pikafish.com](https://www.pikafish.com/)（官网「新手整合包」自带界面，更适合从零开始）
>
>    Windows 版选 `Pikafish-Windows-x86-64-universal.exe` 这种**通用版**即可，
>    它会自动识别 CPU 指令集；发布包**已自带** `pikafish.nnue` 权重，不用另外下。
> 2. 把 `config.example.json` 复制成 `config.json`，改两处：
>    `engine_path` / `nnue_path` 指向引擎实际路径，`api_key` 填自己的
>    DeepSeek key（[申请地址](https://platform.deepseek.com/)）。
>    这个文件已在 `.gitignore` 里，不会被提交。

双击 **`启动.bat`**。黑窗口出现 `[OK] 引擎已就绪` 后，**浏览器会自动打开**
`http://127.0.0.1:8760`；没自动开就手动访问：

```
http://127.0.0.1:8760
```

只监听本机 `127.0.0.1`，不对外网开放。

- **重复双击也没事**：如果服务已经在跑，窗口会提示"端口已在监听"并直接帮你开浏览器，
  不会起第二个实例、不会白占内存。
- **停止**：在那个黑窗口按 `Ctrl+C`。
- 不想自动开浏览器：`启动.bat` 后面加 `--no-browser` 参数，或设环境变量 `XQ_NO_BROWSER=1`。

> ⚠️ **不要往 `启动.bat` 里写中文**。cmd.exe 解析批处理文件时用的是系统 OEM 代码页
> （中文 Windows 是 GBK），UTF-8 的中文会被解成乱码，然后被当成命令去执行，报
> `'?鐨崱楸?+' 不是内部或外部命令，也不是可运行的程序`。所有中文提示都由
> `server.py` 输出（它自己处理 UTF-8），批处理保持纯 ASCII。

## 二、用法

### 1. 教练模式（分析单个局面 / 单步）

1. 在棋盘上点自己的棋子 → 点目标格落子（会显示可落点绿点）
2. 点 **「讲解我这一步」** → 工具会对比"引擎推荐"和"你走的"，给出完整讲解
3. 或者点 **「分析当前局面」** → 讲这个局面该怎么走、各候选的优劣
4. 只想看数据不想叫大模型？点 **「计算当前局面」**（见下面的按钮分工表）
5. 有疑问就在下面的输入框 **追问**，比如"为什么不能吃这个卒？""那我下一步该干嘛？"
   （问答记录会一条条往下排，**输入框始终跟在最新那条追问下面**）

三个按钮的分工（**算**和**讲**是两件事，故意拆开的）：

| 按钮 | 皮卡鱼计算 | 云库 | 大模型讲解 |
|---|---|---|---|
| **计算当前局面** | ✓ | ✓ | ✗ |
| **分析当前局面** | ✓ | ✓ | ✓ |
| **讲解我这一步** | ✓（分析你走这一步之前的局面） | ✓ | ✓ |

同一个局面先点过「计算」，再点「分析」会**直接用刚才的结果接着讲**，
不会重复跑引擎（引擎侧也有缓存）。所以"先算、看数据、再决定要不要讲"是最省的用法。

棋盘上会显示：
- 黄圈 = 上一步走的棋
- 绿箭头 = 引擎推荐的着法（只在分析当前局面时显示）

勾上 **「自动计算当前局势」**（默认开）→ 你每走一步，工具会自动跑一次皮卡鱼 + 云库，
下面两张表和棋盘上的绿箭头立刻跟着更新。它**只算不讲** —— 不会去叫大模型，
所以既不花钱也不用等讲解；嫌每步都算太吵就把勾去掉，改成手动点「计算当前局面」。

### 2. 对弈模式（和皮卡鱼下整盘棋）

它和教练模式是**两盘互不干扰的棋**：在对弈里走子，不会碰掉教练模式的讲解、
追问和预演；反过来也一样。两边只有两条通道 —— 「读取对弈棋局」和「送去复盘」。

1. 选 **「我执」红方 / 黑方**（本局还没走过子的话，选完会自动按新执方重开）
2. 点 **「新开一局」**；AI 先手时会立刻替你走第一步
3. 在棋盘上点自己的棋子 → 点目标格落子（有绿点提示，黄圈标上一步）
4. AI 走完，右栏会给出它这一步的评分（红方视角）、深度和耗时

| 按钮 | 作用 |
|---|---|
| **新开一局** | 按当前执方重开（象棋红先） |
| **悔棋** | 一次退掉"我一手 + AI 的回应"，回到又轮到你走 |
| **翻转** | 对弈棋盘上下翻转（和教练模式的翻转各管各的） |
| **认输** | 结束本局 |
| **AI 深度** | 对弈专用的引擎深度，**和讲解深度是两套**（见「五、配置」） |

**存棋 / 导出**（右栏「保存 / 导出」）：

| 按钮 | 作用 |
|---|---|
| **保存这盘棋** | 存进浏览器本地（最多留 30 盘），列表里可以「载入」或「删除」 |
| **复制棋谱** | 棋谱复制到剪贴板 |
| **导出 .txt** | 下载成文件。**里面是纯棋谱，一行注释都没有** —— 复盘是按空格切词逐个认着法的，掺注释会直接报"没识别出合法着法" |
| **送去复盘** | 把棋谱填进「整盘复盘」的输入框并切过去，点「开始复盘」即可逐手分析 |

想把刚下完的棋拿到教练模式里细讲？回教练模式点 **「读取对弈棋局」** ——
局面、着法记录、最后一步都会搬过去，「分析当前局面」「讲解我这一步」立刻可用。
（自己摆的残局、还没走过子的局面，也一样能读。）

**自己摆一个局面再开局（排残局练手）**：点 **「编辑局面」**。
它和教练模式那个「编辑局面」是**同一套操作**（左键选中 → 左键放下、右键移出到棋子盒、
撤销编辑、清空棋盘、摆回开局、换该谁走），只是摆的是对弈这盘棋。
摆好后点 **「用这个局面开局」**，就用它当这一局的起点，AI 照常应战。

| 编辑时出现的按钮 | 作用 |
|---|---|
| **用这个局面开局** | 以当前摆好的局面开一局（若轮到 AI，它会立刻走） |
| **撤销编辑** | 退一步（编辑态下点「悔棋」也是这个） |
| **清空棋盘** | 清光，32 枚棋子进棋子盒 |
| **摆回开局** | 恢复标准开局 |
| **该谁走：红方 / 黑方** | 指定这一局先走的一方 |

- 摆的过程中 **AI 一步都不会走**，也**不会动教练模式那盘棋**
- 局面不合法（比如**将帅照面**、某一方没有将）会当场红字提醒，改好自动消失
- 摆出来的局面会成为**这一局的起点**：右栏「对局信息」标成「起点局面：自设」，
  存档 / 导出 / 送去复盘都会带着它 —— 所以从残局开始的棋，复盘不会错当成从标准开局走
- 反悔了？「退出编辑」不会用摆的局面开局，点「新开一局」即回到标准开局

> 将死、困毙、认输都会结束本局：棋盘左上角标「本局结束」，右栏写明结果。
> 将死和困毙都判走子方负（中国象棋规则）。

### 3. 整盘复盘

1. 切到顶部 **「整盘复盘」**
2. 粘贴棋谱，**中文记谱和坐标都认**：

   ```
   炮二平五 马8进7 马二进三 车9平8 车一平二 卒7进1
   ```
   或者 `h2e2 h9g7 h0g2`，带 `1. 2.` 手数序号也没问题。

3. 点「开始复盘」→ 逐手分析，给出：
   - **局势曲线**：一眼看出哪几手把优势送掉了
   - **失着清单**：损失多少厘兵、判定（不精确/失误/漏着）、引擎推荐什么
   - 点清单里的「讲解」→ 直接跳到教练模式，详细讲这一步
   - **AI 复盘报告**：总评 + 三阶段 + 关键转折点 + 你的习惯性问题 + 练习建议

建议一次放 20~60 手（深度 14 每手约 0.3~1 秒）。

### 4. 编辑局面（自己摆盘，不用开鲨鱼象棋）

点棋盘下面的 **「编辑局面」** 进入编辑模式，**棋盘右侧**会展开 **棋子盒**
（这样不用上下滚动页面）。操作方式跟鲨鱼象棋一致：

> 对弈模式里也有一个 **「编辑局面」**，操作方式和这一模一样，用来摆残局练手 ——
> 见上面「2. 对弈模式」。两边共用同一套编辑逻辑，所以手感不会有两样。

| 操作 | 效果 |
|---|---|
| **左键点棋子** | 选中它（棋子跟着鼠标走，原格留虚线虚影） |
| **左键再点一个空位** | 把选中的棋子放在那里 |
| **右键点棋子** | 直接把它**移出棋盘**，落到右侧的棋子盒里 |
| **左键点棋子盒里的棋子** | 选中它（来自盒子），再左键点棋盘空位就能放上去 |
| **选中时点另一枚棋子** | 改成选中那一枚；手上这枚留在原处，不会丢 |
| **选中时点它自己 / 按 Esc** | 取消选中，棋子留在原处 |
| **点「清空棋盘」** | 32 枚全进棋子盒，从零摆一个局面 |
| **点「摆回开局」/「撤销编辑」** | 回到开局 / 退回上一步编辑 |

**想把棋子放到别人占着的格子上**（比如换掉一个挡路的卒）：先**右键**把它的
棋子移进棋子盒，再左键放下你要放的棋子。两下，谁都丢不了 —— 鼠标悬停时棋盘上
会直接写清楚"点下去会发生什么"（放下 / 改为选中这个子 / 取消选中）。

另外：

- 编辑模式**不做合法性限制**（那正是编辑的意义），能摆出九宫外的帅、将帅照面等等；
  一旦摆出不合法局面，棋盘下方会实时给出**红字提示**告诉你哪里不对、为什么不能分析。
- 摆完点 **「退出编辑」**，再点「分析当前局面」，就能让引擎评一评你自己摆的局面
  （非常适合做杀法练习、残局研究）。
- **改动过**才清空"着法记录"（因为摆出来的局面不再由前面的着法产生）；只是进去看一眼
  又退出来，局面和着法记录会原样还给你。
- 编辑模式里还有个 **「该谁走」** 开关（红方/黑方）—— 同样的摆子轮谁走完全是两个局面。

### 5. 界面布局：左右两栏各自滚动

**整个页面不滚动**，顶栏固定，棋盘在左、讲解在右，两栏**各自独立滚动**：

- 鼠标放在讲解区往下滚 → **只有讲解在动，棋盘纹丝不动**（这是重点，长讲解不用再上下翻页找棋盘）。
- 左栏内部也做了顺序：窗口不够高时**先压缩"着法记录"**（它自己滚动），棋盘卡片不参与压缩，
  所以棋盘永远完整可见。
- **窗口宽度 ≤1180px** 时左右栏放不下，会自动堆成一栏并回到整页滚动（单栏下"独立滚动"更难用）。
- 顶栏那个 **「整盘复盘」** 标签页也是同一套规则。

### 6. 讲解里不会出现字母坐标

讲棋只用**中文说法**，不会有 `a0`、`h2`、`b7` 这种格子坐标：

| 场合 | 写法 |
|---|---|
| 指某枚棋子 | 红方九路车、黑方 3 路炮（路数从各自右手边数起） |
| 指某条横线 | 从红方数第 3 条横线（从各自底线数起） |
| 说一步棋 | 中文记谱：炮二平五、马8进7 |

两层保障：**材料里根本不出现坐标**（棋盘不带 a..i 列标、候选表不列 UCI、
云库着法转成中文，另附一份「子力位置」中文清单供模型照抄），
**输出再过一道兜底翻译**——万一模型还是写了 `a0`，也实时改写成
「红方九路车」（`xq/zh.py`），界面上永远看不到坐标。

### 7. 追问 = 只答所问，不会又讲一遍局面

讲解下方的输入框（"追问，例如：那我现在该走什么？"）走的是**另一条提示词**：

- 只回答问的那一件事，**不重新讲解局面**，也不许写
  「一句话结论 / 局面态势 / 最佳着法好在哪 …」那六个小节标题；
- **不许复述**子力对比、每子在几条横线、候选着法表；
  只有直接支撑答案的一两项数据可以一句话带过；
- 篇幅 150~350 字，最多 3 条；
- 讲完讲解后正文会留一份副本一起发过去，模型知道"这些我已经说过了"；
- 追问材料也做了瘦身（去掉 ASCII 棋盘），从源头减少"照抄一遍局面"的诱因。

换局面 / 新开一局 / 载入 FEN 时会自动清掉旧讲解副本，避免串场。

**追问记录的位置**：问答按时间**从上往下排**（新的在下面），
输入框排在整片问答记录的**最下方** ——
所以它永远紧跟最新那条追问，不会卡在讲解和问答之间。

**追问记录什么时候清空**：**「讲解 + 追问」是一组，换局面就是新的一组。**
点「计算 / 分析当前局面」或「讲解我这一步」时，如果这次分析的局面和上一组不同
（走了一步、换了 FEN、编辑过棋盘都算），旧的问答会整片清掉，
新讲解下面不会再挂着上一个局面的问答。
同一个局面重复分析（先点「计算」再点「分析」）算同一组，问答会留着。
另外：还没分析就点「追问」会提示先分析，不会点了没反应。

### 8. 预演摆盘（照着讲解里的预演摆盘，讲解不会消失）

讲解和候选表里都会给"引擎预演"这条线（例如 炮八平六 → 车1平2 → …）。
**想照着摆到棋盘上看一看**时，用**预演摆盘**，别再手动走子或去编辑局面 ——
以前那样做，第一次改动就会把讲解、追问记录、候选表全清掉。

怎么用：

1. 在「引擎候选着法（皮卡鱼）」表里，挑一行点右下角的 **「摆一摆」**；
   「你」那一行也有（那条线以你走的着法开头）。
2. 棋盘下方出现 **预演摆盘控制条**：
   | 按钮 | 作用 |
   |---|---|
   | ⏮ 起点 / ◀ 上一步 / 下一步 ▶ | 一步一步摆，棋盘角上实时显示「预演 3/9」 |
   | 自动播放 | 每 0.95 秒走一步，再点一次暂停 |
   | 着法条（1.炮八平六 2.车1平2 …） | 点任意一步直接跳过去，红黑分色，当前步高亮 |
   | **按此线接着下** | 把已经摆过的几步**真的走到棋盘上**（记入着法记录），然后退出预演 |
   | 退出预演 | 棋盘回到你的真实局面，一切如初 |
3. 预演期间棋盘上**点子是无效的**（并会提示你），因为那是"虚拟局面"，
   不可能在这上面真的走子 —— 想自己走就用下面第 8 节的**自由推演**。
4. 想自己接着这个局面走？点左边的 **「自由推演」**，会从你现在摆到的这一步接下来，
   原来那条线的着法条还留着。

关键点：**预演期间 `state.board`、着法记录、讲解正文、追问记录一律不动** ——
所以摆多久讲解都在。点「按此线接着下」之后，棋盘就是这条线的局面，
**讲解正文也会保留**（只是在最上面加一条说明："这是原来那个局面的讲解，
照着预演摆了 N 步，仅供参考"），接着走一步再点「讲解我这一步」就能评价这条线。

### 9. 自由推演（棋盘上自己随手走，讲解不会消失）

「摆一摆」只能按引擎/云库给的那条线走。想自己试"如果我这步走这里会怎样"，
用 **「自由推演」**（按钮就在「编辑局面」旁边）。

- 点「自由推演」→ 棋盘下方出现控制条，**直接在棋盘上走子**：红黑双方随你走，
  引擎不插手（走法合法性仍由同一套规则引擎判，非法走不出来）。
- 想换一种走法：点 **「◀ 上一步」** 退回去再走（后面的着法会作废，避免前后矛盾）。
- 着法条、⏮/◀/▶、自动播放 都和「摆一摆」共用一套，用法一样。
- 觉得可以了，点 **「落到棋盘」** → 把这些步**真的走到棋盘上**（记入着法记录）；
  点「退出推演」则弃掉推演，棋盘回到真实局面。

和「摆一摆」的关系（**互不冲突**）：

| 场景 | 行为 |
|---|---|
| 正在「摆一摆」→ 点「自由推演」 | **从你摆到的那一步接着自由推演**，着法条不清 |
| 正在「自由推演」→ 点「自由推演」 | 退出推演，回到真实局面（按钮文案会变成「退出推演」） |
| 正在「自由推演」→ 点候选表「摆一摆」 | 按那张表那条线重开，原来的推演丢弃（按钮文案变回「自由推演」） |

关键点同第 7 节：**推演全程 `state.board`、着法记录、讲解正文一律不动**，
只有点「落到棋盘」才会真的改棋盘，而那时讲解正文依旧保留。

## 三、配合鲨鱼象棋使用

你已有的鲨鱼象棋负责"看盘、连线、下棋"，本工具负责"讲清楚为什么"。
两者的衔接方式是**复制棋谱 / FEN**：

| 你在鲨鱼象棋里做的 | 在本工具里做的 |
|---|---|
| 棋谱窗口 → 复制棋谱（鲨鱼支持**复制粘贴棋谱**，棋谱可以不带 FEN 串） | 切到「整盘复盘」→ 粘贴 → 开始复盘 |
| 对局中随时复制当前局面 FEN（鲨鱼支持**粘贴棋谱/局面**，局面可带 moves） | 点「粘贴 FEN」→ 再点「分析当前局面」 |
| 引擎窗口的**思考细节可复制** | 想知道某一步的后续，直接看本工具的「引擎预演」列 |

两点提醒：

1. **分数口径不同**。鲨鱼象棋的分数有三种显示模式（红分 / 己分 / 原始），
   默认是「己分模式」——也就是**以你执的那一方为基准**。本工具为了不产生歧义，
   永远同时给出「走子方视角」和「红方视角」两列，并统一用**厘兵**为单位
   （鲨鱼状态栏上的 `+1.50` 就是本工具的 `+150`）。
2. **连线对局也算数**。鲨鱼记录棋谱时会带上引擎名称和优劣分值，
   但本工具不看这些，会**重新用自己的引擎逐手复算**一遍，
   所以能得到每手的真实代价，而不是只看到引擎当时那一行分数。

## 四、界面上的数字怎么看

| 名词 | 含义 |
|---|---|
| **厘兵** | 分数单位。100 厘兵 = 一个兵的价值。差值 100 大致相当于亏一个兵 |
| **走子方视角** | 正数 = 该走棋的一方占优 |
| **红方视角** | 正数 = 红优。判断局面看这个 |
| **胜/和/负** | 千分比，例如 `51/933/16` = 胜 5.1%、和 93.3%、负 1.6% |
| **损失** | 你这手比引擎最佳着法多丢的厘兵。<br>`≤20` 好棋 · `≤60` 略有不准 · `≤150` 不精确 · `≤300` 失误 · `>300` 严重失误 |
| **云库评级** | `!` 最佳着法 · `*` 合理着法 · `?` 错漏着法（来自实战+分布式计算） |
| **快速模式** | 勾上=大模型不思考，几秒出答案；取消=会先思考，讲得更细（首次出字约 40~60 秒，思考过程会实时显示） |

**最重要的一句**：云库看的是"实战里大家怎么走"，引擎看的是"当前局面算下来怎么样"。两者不一致的地方，就是你最该琢磨的地方。

## 五、配置

`config.json` 不在仓库里（含密钥，已被 `.gitignore` 忽略），首次使用从模板复制：

```
copy config.example.json config.json      # macOS / Linux 用 cp
```

然后编辑 `config.json`：

```json
{
  "engine_path": "D:\\Pikafish\\皮卡鱼-Pikafish\\Pikafish-Windows-x86-64-universal.exe",
  "threads": 8,              // 引擎线程数，按 CPU 核心数设
  "hash_mb": 1024,           // 哈希表大小
  "api_key": "sk-...",       // DeepSeek key
  "base_url": "https://api.deepseek.com/v1",
  "model": "deepseek-flash", // 也可用 deepseek-v4-pro（更慢更强）
  "reasoning_effort": "low", // 思考程度：low / none / high
  "analyze_depth": 18,       // 讲解 / 分析局面的搜索深度
  "play_depth": 12,          // 对弈模式 AI 走子的深度（和讲解深度互相独立）
  "review_depth": 14,        // 整盘复盘的深度（越低越快）
  "multipv": 4,              // 候选着法条数
  "cloud_enabled": true,     // 是否查象棋云库
  "port": 8760
}
```

改完重启服务生效。也可以直接在界面右上角的 **「⚙ 设置」** 里改
（讲解深度 / 对弈深度 / 复盘深度 / 候选条数 / 思考强度 / 云库开关）——
在那里改会写回 `config.json`，**下一次分析或走子就生效，不用重启**。

> 设置界面只开放上面这几个"算法参数"字段。`api_key`、`engine_path`、
> `port` 这类**故意没有开放**（不给网页开后门去改凭据、改引擎路径、改监听端口），
> 想改请直接编辑 `config.json`。

**讲解深度 vs 对弈深度**：这是两个独立的数值，别混用 ——
讲解要"讲得准"，深度开高（默认 18）；对弈要"下得快"，深度开低（默认 12）。
把对弈深度开到 18 会让 AI 每步思考好几秒，把讲解深度压到 12 则结论会糙一些。

## 七、说明与注意事项

- **中文记谱**是本工具自己实现的核心能力。引擎给的是 `h2e2` 这种坐标，
  界面和讲解里全部翻译成 `炮二平五`，否则你读不下去。
- **防幻觉**：提示词里明确禁止大模型编造棋子位置，所有局面、着法、
  分数、预演线都由引擎和云库提供，模型只负责措辞。万一它还是说错了，
  以「引擎候选着法」表为准。
- **非法局面会被拦住**：棋子数量超限、将帅照面、该走棋方被将军等，
  工具会直接提示而不会拿去分析（象棋引擎在非法局面上会给出失真结果）。
  用「编辑局面」摆出来的局面同样要过这一关 —— 摆的过程中棋盘下方就会提示。
- **云库覆盖范围**：主要覆盖开局和常见中局，冷门局面查不到是正常的。
- 复盘的「平均损失」这一项，业余爱好者通常在 60~120 厘兵之间，
  能压到 40 以下已经很稳了。

## 八、换个模型 / 用别的 API

改 `config.json` 的 `base_url` + `model` + `api_key` 即可，任何兼容
OpenAI `/chat/completions` 格式的服务都能用（包括本地 Ollama）。
